# Глава 9: Проектирование поискового робота (Web Crawler)

## Введение
**Поисковый робот (web crawler)**, также известный как паук (spider) или бот, используется для обнаружения и сбора веб-контента: веб-страниц, изображений и видео. В этой главе мы проектируем масштабируемый поисковый робот для **индексации поисковой системой**.

### Области применения поисковых роботов
1. **Индексация для поисковых систем:** сбор веб-страниц для построения поисковых индексов (например, Googlebot).
2. **Веб-архивирование:** сохранение данных из интернета для будущего использования (например, Библиотека Конгресса США).
3. **Веб-майнинг:** извлечение знаний из веб-данных (например, финансовый анализ отчётов для акционеров).
4. **Веб-мониторинг:** выявление нарушений авторских прав и прав на товарные знаки.

### Сложности проектирования
Хороший поисковый робот должен обеспечивать:
- **Масштабируемость:** обработку миллиардов страниц за счёт распараллеливания.
- **Отказоустойчивость:** корректную работу с невалидным HTML, сбоями и вредоносными ссылками.
- **Вежливость (politeness):** отсутствие перегрузки серверов слишком большим числом запросов.
- **Расширяемость:** поддержку новых типов контента с минимальными изменениями.

---

## Шаг 1: Понимание задачи

### Требования
1. Обходить **1 миллиард веб-страниц в месяц** (400 страниц/с, пиковая нагрузка 800 QPS).
2. Собирать **только HTML-контент**.
3. Отслеживать новые и обновлённые страницы.
4. Игнорировать дублирующийся контент.
5. Хранить собранные данные **5 лет**, что требует ~30 PB хранилища.

## Шаг 2: Высокоуровневый дизайн

### Компоненты

<img src="./images/web-crawler-architecture.png" alt="Архитектура поискового робота" width="700">
</p>

1. **Начальные URL (seed URLs):** отправные точки для робота.
    - Их нужно выбирать тщательно: хорошая отправная точка позволяет роботу обойти как можно больше ссылок.
    - Можно исходить из географического принципа (популярные сайты в разных регионах) или из тематики.
    - Стратегии: классификация по географии или по теме (например, спорт, здравоохранение).

2. **Очередь URL (URL Frontier):** хранит URL, которые предстоит загрузить.
   - Реализуется как **FIFO-очередь**.

3. **Загрузчик HTML (HTML Downloader):** скачивает веб-страницы по URL, полученным из URL Frontier.

4. **DNS-резолвер:** преобразует URL в IP-адреса.

5. **Парсер контента (Content Parser):** проверяет и разбирает веб-страницы.
   - Отбрасывает некорректно сформированные страницы.

6. **Content Seen? (контент уже встречался?):** проверяет наличие дубликатов через сравнение хешей (сравниваются хеш-значения двух веб-страниц).

7. **Хранилище контента (Content Storage):** хранит HTML-страницы на диске (популярный контент — в памяти, чтобы снизить задержку).

8. **Извлекатель URL (URL Extractor):** извлекает новые ссылки из разобранных страниц.

9. **Фильтр URL (URL Filter):** исключает URL из чёрного списка и ошибочные URL.

10. **URL Seen? (URL уже встречался?):** отслеживает посещённые URL, чтобы избежать дублирования.

11. **Хранилище URL (URL Storage):** хранит уже посещённые URL.


---

### Рабочий процесс
1. Добавляем **начальные URL** в URL Frontier.
2. **Загрузчик HTML** забирает URL и определяет их IP-адреса через DNS-резолвер.
3. **Парсер контента** проверяет страницы и передаёт контент компоненту «Content Seen?».
4. Если контент новый, извлекаем ссылки с помощью **URL Extractor**.
5. Фильтруем ссылки и добавляем уникальные в URL Frontier.

## Шаг 3: Детальный разбор ключевых компонентов
### DFS/BFS
-  Веб можно представить как ориентированный граф, где веб-страницы — вершины, а гиперссылки (URL) — рёбра.
-  Для обхода графа обычно используют BFS (поиск в ширину), поскольку глубина может быть очень большой, и DFS (поиск в глубину) здесь плохо подходит.
-  Стандартный BFS не учитывает приоритет URL, а ведь не все страницы одинаково качественны и важны.


### URL Frontier
- **Вежливость (politeness):** 
    - Гарантируем не более одного запроса к хосту одновременно. Добавляем задержку между двумя задачами загрузки.
    - Используем отображение имён хостов на очереди и рабочие потоки (загрузчики).
    - У каждого потока-загрузчика своя отдельная FIFO-очередь, и он скачивает URL только из неё.

        <img src="./images/politeness.png" alt="Вежливость" width="500">

    - **Маршрутизатор очередей (Queue router):** гарантирует, что каждая очередь (b1, b2, … bn) содержит URL только одного хоста.
    - **Таблица соответствий (Mapping table):** сопоставляет каждому хосту очередь.
    - **Селектор очередей (Queue selector):** каждый рабочий поток привязан к своей FIFO-очереди и скачивает URL только из неё. Логика выбора очереди реализована в селекторе очередей.
    - **Рабочие потоки с 1 по N.** Рабочий поток последовательно скачивает веб-страницы с одного хоста. Между двумя задачами загрузки можно добавить задержку.

- **Приоритет:** 
    - Назначаем более высокий приоритет важным страницам (например, по PageRank или частоте обновлений).

        <img src="./images/prioritizer.png" alt="Приоритизатор" width="500">
    
    - **Приоритизатор (Prioritizer):** принимает на вход URL и вычисляет их приоритеты.
    - **Очереди с f1 по fn:** у каждой очереди свой приоритет. Очереди с высоким приоритетом выбираются с большей вероятностью.
    - **Селектор очередей (Queue selector):** случайно выбирает очередь с перевесом в пользу очередей с более высоким приоритетом.
    - **Передние очереди (front queues):** отвечают за приоритизацию.
    - **Задние очереди (back queues):** отвечают за вежливость.

- **Свежесть (freshness):** повторный обход на основе истории обновлений или важности страницы.


### Загрузчик HTML
- **Соблюдение robots.txt:** уважаем правила из файлов robots.txt.
- **Оптимизации производительности:**
  1. Распределённый обход с использованием нескольких серверов.
  2. Использование **DNS-кеша**, чтобы не выполнять повторные запросы к DNS.
  3. Географическое распределение серверов обхода для более быстрой загрузки.
  4. Короткий таймаут, чтобы не зависать на медленных или неотвечающих серверах.

### Отказоустойчивость
1. **Консистентное хеширование (consistent hashing):** эффективное распределение нагрузки между серверами.
2. **Обработка ошибок:** защита системы от падений из-за исключений.
3. **Валидация данных:** обеспечение целостности контента.

### Расширяемость
- Добавляем модули для новых типов контента (например, загрузчик PNG, веб-монитор).
- Пример: подключаем модуль для мониторинга веб-контента на предмет нарушений авторских прав.

    <img src="./images/extensibility.png" alt="Расширяемость" width="600">

### Избегание проблемного контента
1. **Дублирующийся контент:** выявляем через сравнение хешей.
2. **Ловушки для пауков (spider traps):** избегаем бесконечных циклов, например ограничивая длину URL.
3. **Информационный шум:** отфильтровываем нерелевантный контент вроде рекламы и спама.

---

## Шаг 4: Подведение итогов
### Ключевые выводы
1. Поисковый робот должен балансировать между масштабируемостью, отказоустойчивостью, вежливостью и расширяемостью.
2. **Вежливость** предотвращает перегрузку серверов, а **приоритизация** гарантирует, что важные страницы будут обойдены первыми.
3. Эффективное хранение и обработка ошибок критически важны для обхода в больших масштабах.

### Дополнительные соображения
- **Рендеринг на стороне сервера (server-side rendering):** обработка динамического контента, генерируемого JavaScript или AJAX.
- **Меры против спама:** исключение низкокачественных и нерелевантных страниц.
- **Шардирование базы данных:** масштабирование слоя данных с помощью репликации и шардирования.
- **Горизонтальное масштабирование:** использование серверов без состояния (stateless) для эффективного масштабирования задач обхода.
- **Аналитика:** сбор и анализ данных для получения инсайтов.
